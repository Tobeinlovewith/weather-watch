# 天气守护 · Weather Watch

给个人 QQ 用的天气播报与雨雪预警系统。重点不是「查天气」，而是**在雨雪真正落下来之前叫住你**，并且把话说得像人话。

> 数据源：和风天气（分钟级降水）+ 中国天气网（预报/预警）+ 中央气象台（官方实况与预警）

## 它能做什么

### 三类定时播报

| 时间 | 内容 |
| --- | --- |
| 06:00 | 今天：天气、温度、实况体感、穿衣、空气质量 |
| 12:00 | 下午到夜里：剩余时段天气 + 「晚点会更凉，外套别落下」 |
| 21:00 | 明天：天气、温度、穿衣、逐段温度，按星期给不同收尾 |

播报里带农历、二十四节气（24 条各配一句应景话）、穿衣建议、空气质量建议。

### 降水预警

- **提前 15 分钟**告诉你「还有 8 分钟就下小雨了，如果要出门的话记得带伞哦~」
- 按**强度分级**措辞：小雨 / 中雨 / 大雨 / 暴雨，雪同理（小雪→暴雪），冰雹单独一类
- 雨**已经在下**时说「已经开始下小雨了」
- 雨**停了**说「雨停了，接下来一小时没雨」

### 三级降级审查（省 → 市 → 区县）

1. **省级**：查该省全部城市站点的预报，统计多少城市未来 48 小时有降水
2. **市级**：三个数据源各自表态（和风 24h 逐小时 / 中国天气网 3 小时 / 中央气象台站点），**少数服从多数**
3. **时间**：多源都判有雨时，取**最早**的那个开始时间

每天 3 次静默审查（00:00 / 12:00 / 18:00），**没雨就不查分钟级**，省 API 配额。

### 气象预警

- 抓官方预警列表，按城市层级过滤（洛宁县的预警不会算到洛阳市）
- 自动过滤已过期、已解除的预警
- 之前推过、现在消失的预警会补一条「✅ 已解除」
- 每种预警附**具体建议**：大雾→「骑车开灯放慢」，道路结冰→「尽量别骑两轮车」

### 群聊交互

| 你说 | 它回 |
| --- | --- |
| 今天天气怎么样 / 天气 | 订阅城市的完整早报 |
| 明天天气 | 明天的晚报内容 |
| 成都天气 | 只回成都 |
| 明早会不会下雨 / 今晚有雨吗 | 是非判断 + 完整预报 |
| `#加城市 上海` | 添加订阅城市 |
| `#删城市 上海` / `#城市列表` | 管理订阅 |

闲聊不插嘴（「今天天气真好啊」不会触发）。

## 架构

```
┌─────────────────────────────────────────────────┐
│ 看门狗 watchdog.pyw（端口 47820）                │
│  · 每 30 秒确认下面三个在跑                       │
│  · 心跳超 10 分钟未更新 → 判定假死 → 杀进程重拉     │
│  · 三次拉起失败 → 强制结束 → 写 GIVEUP 放弃        │
│  · QQ 掉线超 5 分钟 → 发告警                      │
└───────┬──────────────┬──────────────┬───────────┘
        │              │              │
 ┌──────▼─────┐ ┌──────▼──────┐ ┌─────▼──────────┐
 │ rain_watch │ │cmd_listener │ │ qqbot_service  │
 │ 端口 47821 │ │ 端口 47822  │ │ 端口 47825     │
 │ 判定+播报   │ │ 群指令+问答 │ │ 官方机器人遥控 │
 └──────┬─────┘ └──────┬──────┘ └─────┬──────────┘
        │              │              │
        └──────────────┴──────────────┘
                       │
                 OneBot WebSocket
                  ws://127.0.0.1:3001
                       │
                  第三方 QQ 客户端
```

### 数据流

```
和风 minutely ─┐
中国天气网 3h ─┼→ 多源投票 → 计划器（armed/idle）→ 提醒消息
中央气象台 ────┘         ↓
                    提前 30 分钟进入监控
                    每分钟查一次分钟级
                    提前 15 分钟提醒
```

## 快速开始

### 1. 依赖

只需要 Python 3.10+，其余全部标准库。可选：

```bash
pip install cnlunar      # 农历与节气（不装则自动跳过农历行）
```

### 2. 配置

```bash
cp config.example.json config.json
```

填这几项：

| 字段 | 说明 |
| --- | --- |
| `qweather.key` / `qweather.host` | 和风天气 API（免费额度 5 万次/月） |
| `locations` | 城市列表：`name`、`city_code`（中国天气网编码）、`lat`/`lon` |
| `qq.targets` | 推送目标：`private` 填 QQ 号，`group` 填群号 |
| `commands.group_id` / `owner` | 允许执行指令的群与管理员 QQ |
| `qqofficial` | 可选，QQ 官方机器人（掉线告警 / 远程遥控） |

### 3. 启动

```powershell
# 只跑守护（需要本机已有 OneBot WebSocket 在 3001）
pythonw watchdog.pyw

# 前台调试
python rain_watch.py --loop
python rain_watch.py --once        # 跑一轮看结果
python rain_watch.py --check       # 检查数据源连通性
```

### 4. 测试

```bash
python -m unittest discover -s tests -v
```

## 运维

```powershell
python go.py 检查      # 全量体检
python go.py 救活      # 重启第三方 QQ + 拉起全部守护
python go.py 停        # 置 STOP，全部退出
python go.py 恢复      # 删 STOP，重新拉起
```

**紧急停止**：在项目根目录新建一个名为 `STOP` 的空文件，守护会在 1 分钟内自己退出，看门狗也不会再拉起。

**放弃管理**：出现 `GIVEUP` 文件时说明连续三次启动失败、已强制结束并放弃。删除该文件可恢复。

## 安全提示

- `config.json` 含密钥，**不要提交到仓库**（已在 `.gitignore` 里）
- QQ 官方机器人的 AppSecret 泄露后请立即在 q.qq.com 重置
- 官方机器人发消息需要在控制台配置**本机公网 IP 白名单**

## 已知限制

- 分钟级降水只有一家数据源（和风），它挂了会退回 3 小时粒度
- 第三方 QQ 客户端（如 NapCat / SnowCat）属于非官方协议，存在封号风险
- 电脑关机 / 断网时无法发出任何告警
