# 运维手册

> 给三个月后的自己（以及接手的 AI）看的。所有命令在 `weather_watch` 目录下执行。

## 一、这套东西是什么

个人 QQ 天气播报系统。三个功能：

1. **雨雪提前提醒**：判到要下雨/雪，提前 15 分钟推消息，按强度分级措辞
2. **每天三次播报**：06:00 今天 / 12:00 下午到夜里 / 21:00 明天
3. **群内问答**：今天天气怎么样 / 明天天气 / 成都天气 / 明早会不会下雨

## 二、进程拓扑

```
计划任务 DSH-Weather-Daemons（每 5 分钟）
   └─ 只在看门狗没跑时拉起它
        └─ watchdog.pyw（端口 47820，常驻）
             ├─ rain_watch.py    （47821）取数 + 判定 + 播报
             ├─ cmd_listener.py  （47822）群指令 + 天气问答
             └─ qqbot_service.py （47825）QQ 官方机器人遥控
```

**外部依赖**：第三方 QQ 客户端（SnowCat）提供 `ws://127.0.0.1:3001` 的 OneBot 接口。

| 端口 | 谁 | 不通时怎么办 |
| --- | --- | --- |
| 3001 | 第三方 QQ 的 OneBot | `go.py 救活` |
| 6099 | SnowCat WebUI | 同上，起来后扫码 |
| 47820 | 看门狗 | 计划任务会拉起 |
| 47821 | 雨天守护 | 看门狗会拉起 |
| 47822 | 指令监听 | 同上 |
| 47825 | 官方遥控服务 | 同上（启动慢，等 50 秒） |

## 三、日常命令

```powershell
python go.py 检查      # 全量体检（含代码新旧自检）
python go.py 救活      # 重启第三方 QQ + 拉起全部守护
python go.py 停        # 置 STOP，全部退出
python go.py 恢复      # 删 STOP，重新拉起
```

**在 QQ 官方机器人里**（不用开电脑）：发 `检查` / `救活` / `停` / `恢复`，会秒回执再给结果。

## 四、紧急停止

三种方式，任选：

1. 双击桌面 **`停止天气守护.bat`**
2. 在 `weather_watch` 目录新建空文件 **`STOP`**（记事本存一下即可）
3. 命令行 `python go.py 停`

`STOP` 存在时，看门狗和守护都会退出，计划任务也不会再拉起。**删掉 `STOP` 才恢复。**

## 五、故障排查表

| 症状 | 判断 | 处理 |
| --- | --- | --- |
| 收不到任何消息 | `go.py 检查` 看 3001 | 3001 不通 → `go.py 救活` |
| 3001 通但发不出 | 看日志 `网络连接异常` | QQ 消息通道坏了 → 重启 QQ（要扫码） |
| 有 `GIVEUP` 文件 | 连续三次拉起失败，已放弃 | 看 `logs/watchdog.log` 找原因，删文件后 `go.py 恢复` |
| 提醒时间偏晚 | 和风分钟级 5 分钟粒度 | 正常现象，最多晚 1~2 分钟 |
| 播报重复 | 存在两套系统同时在推 | AstrBot 插件的 `push_targets` 留空 |
| 日志暴涨 | 已自动轮转（5MB） | 无需处理 |
| 官方机器人 401 | IP 白名单失效 | q.qq.com → 开发设置 → 加当前公网 IP |

## 六、告警链路（第三方挂了怎么通知你）

```
发告警时
 ├─ 第三方 QQ(3001) 通？  → 用它发（真号，最自然）
 ├─ 不通 → QQ 官方机器人  → 主动消息
 ├─ 失败 → 邮件/微信推送  → 需在 config.alert 配置
 └─ 全失败 → 只记日志
```

**QQ 掉线判定**：看门狗每 30 秒探 3001，连续 5 分钟不通就告警；恢复后再发一条「已恢复」。

## 七、数据源

| 源 | 用途 | 限制 |
| --- | --- | --- |
| 和风天气 `/v7/minutely/5m` | **唯一的分钟级降水** | 5 分钟粒度；免费 5 万次/月 |
| 中国天气网 `d1.weather.com.cn` | 实况、逐 3 小时、日预报、生活指数 | 页面结构变了要改解析 |
| 中央气象台 `www.nmc.cn/rest/*` | 官方站点实况、体感、官方预警列表 | 无 key、国内直连、无需代理 |

**为什么不用国际源**：实测 Open-Meteo / met.no / wttr 与官方站点差 2.5~3.5℃、湿度差 15 个百分点，属全球模型格点值，不能用于「现在下没下雨」判断。

## 八、配额纪律

- 只有**进入 armed 状态**的城市才每分钟查分钟级
- 每天 3 次审查（00:00 / 12:00 / 18:00），判无雨直接 idle
- 中国天气网与中央气象台都是免费源，缓存 5~10 分钟
- 满负荷估算：4 城市 × 1 次/分 × 有雨时段，月均 ~4 万次，卡在 5 万额度内

## 九、改代码之后必做

```powershell
python -m unittest discover -s tests      # 44 个测试
python go.py 检查                          # 看有没有「代码比进程新」
```

改成 `idle` 的进程不会自动重载代码。`go.py 检查` 会明确提示哪个脚本需要重启。

## 十、配置项速查（config.json）

| 字段 | 含义 | 调优建议 |
| --- | --- | --- |
| `lead_minutes` | 提前多少分钟提醒 | 15 偏保守；12 更快但误报多 |
| `cooldown_minutes` | 两次提醒最小间隔 | 5，调大防止连环提醒 |
| `planner.scan_times` | 每日审查时刻 | 默认 00/12/18 |
| `planner.arm_lead_minutes` | 有雨时提前多久进监控 | 30 |
| `planner.armed_poll_minutes` | 监控期的查询间隔 | 1（配额允许） |
| `briefing.morning/noon/evening` | 三次播报时间 | 06:00 / 12:00 / 21:00 |
| `quiet_hours` | 免打扰时段 | 留空 |

## 十一、给接手的 AI

如果你是接手这个项目的 AI，先读这几段：

1. **别重复踩的坑**
   - QQ 输入框会把 `qq` 自动转成表情 → 命令行工具名不能含 `qq`（所以有 `go.py`）
   - Windows 下 `SO_REUSEADDR` 不能做单实例锁，必须 `SO_EXCLUSIVEADDRUSE`
   - QQ 官方机器人同一个 `msg_id` 回复必须 `msg_seq` 递增，否则 400
   - 第三方 QQ 的 `Stop-Process` 需要提权
   - GitHub 走 Clash 代理（7897）；SSH 走 `ssh.github.com:443` 不需要代理

2. **改代码的纪律**
   - 改完跑测试，再重启对应进程，最后 `go.py 检查` 确认没有「代码比进程新」

3. **数据结构**
   - `state.json`：`sent_keys`（去重）、`sent_briefs`、`plan`（每城市状态机）、`outbox`（补发队列）
   - `plan[城市]`：`mode`（idle/armed）、`armed_at`、`alerted`、`rain_notified`、`last_poll`

4. **别动的地方**
   - `D:\NapCatBot`（SnowCat 运行时）
   - `D:\AstrBot`（除非在改插件）
